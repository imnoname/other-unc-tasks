# Дизайн программы-распознавателя для ЛР 4

## Цель

Дать запускаемую демонстрацию автомата Мили варианта 20 из отчёта. Пользователь передаёт одно слово и получает траекторию состояний, выходную последовательность и вывод о допустимости.

## Границы

- Одно слово за запуск; интерфейс командной строки Python, стандартная библиотека.
- Повторить автомат отдельно в виде таблицы переходов и выходов, ориентированного графа и матрицы переходов-выходов.
- Показать результат каждого представления, чтобы можно было сравнить их.
- Пустые переходы означают отклонение. Допуск определяется конечными состояниями `{q1, q2, q3}`, включая слово `a` для нулевых повторов циклов.
- Не включать GUI, редактирование автомата, генератор графика или файловый формат описания.

## Подходы

1. Одна общая таблица переходов — проще, но не показывает работу трёх способов задания.
2. Три независимых представления и три прохода — рекомендованный вариант: напрямую соответствует практическому заданию и позволяет проверить совпадение результатов.
3. Интерактивное приложение — лишняя сложность для демонстрации конечного автомата.

## Поведение

Команда вида `python finite_automaton.py acdeee`. Для каждого из трёх представлений программа печатает слово, траекторию состояний, выходы, допустимость и причину отказа, если перехода нет. Неверные символы также отклоняются с ясным сообщением. Выходы: `0` на переходах по `a,b,c,d`, `1` на переходах по `e`; при нулевом суффиксе `e*` принадлежность определяется конечным состоянием.

## Проверка

До реализации будут зафиксированы проверки для `a` (допустимо), `acdeee` (допустимо), `acb` (отказ после допустимого префикса), `ba` (отказ с первого символа), неизвестного символа и отсутствующего аргумента. Результаты трёх форм автомата должны совпасть для каждого слова.
