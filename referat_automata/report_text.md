# ВВЕДЕНИЕ

Конечный автомат описывает обработку входной последовательности с помощью конечного множества состояний. Такая модель позволяет отделить правило обработки данных от конкретной реализации программы. По состояниям и переходам можно проследить, почему слово принято или отклонено, а по выходным сигналам — какие действия выполнены на каждом шаге. Эти свойства делают автоматную модель пригодной для учебного исследования алгоритмов, распознавания формальных языков и построения управляющих устройств.

Цель работы — исследовать и программно реализовать синтез и минимизацию конечного автомата с сохранением его наблюдаемого поведения. Синтез выполняется по регулярному выражению методом мест и подчинения из лабораторной работы №5. Способы представления автомата принимаются по лабораторной работе №4. Минимизация выполняется по лекционному примеру для автомата Мили: сначала состояния группируются по выходам, затем разбиение уточняется по переходам [1–3].

Для достижения цели рассматриваются формальная модель автомата, правила синтеза, критерии эквивалентности и алгоритм получения минимального автомата. Практическая часть включает оконную программу, пошаговый разбор двух примеров, руководство пользователя, автоматические тесты и каталог событий интерфейса. Корректность проверяется двумя разными способами: независимым распознаванием слов исходного языка и точным сравнением исходного и минимизированного автоматов.

Для a⟨b|c⟩d построенный полный автомат сокращается с шести состояний до четырёх, а лекционный автомат Мили — с пяти до трёх. Сохраняются все выходные последовательности; для распознавателя дополнительно сохраняется допустимость пустого слова.

# 1 Теоретические основы конечных автоматов

## 1.1 Формальная модель и функционирование

В ЛР №4 конечный автомат определяется как дискретное устройство, перерабатывающее входные слова в выходные слова. Модель задаётся пятью компонентами: входным алфавитом X, конечным множеством состояний Q, выходным алфавитом U, функцией переходов δ и функцией выходов λ [1]. Для запуска дополнительно выбирается начальное состояние. В режиме распознавания указывается множество конечных состояний F.

!eq S = ⟨X, Q, U, δ, λ⟩
!eq δ : X × Q → Q                 λ : X × Q → U

Порядок аргументов функций сохранён по методичке: сначала входной символ, затем предыдущее состояние. В такт i автомат читает символ x(i), находясь в состоянии q(i−1). По таблице выбираются следующее состояние и выход. Никаких других сведений о предшествующем входе для этого шага не требуется: необходимая история уже представлена текущим состоянием.

!eq q(i) = δ(x(i), q(i−1))          u(i) = λ(x(i), q(i−1))

У автомата Мили выход связан с переходом и зависит от входного символа и предыдущего состояния. У автомата Мура выход определяется состоянием; в принятой в ЛР №4 записи он наблюдается после перехода. Эти модели нельзя смешивать при минимизации: для Мили сравниваются векторы выходов на входных символах, для Мура исходным признаком служат выходные метки самих состояний.

В программе используется детерминированный автомат Мили. Для каждой пары «состояние — входной символ» существует ровно один переход и ровно один выход. В режиме регулярного выражения выходом служит 0 или 1: единица означает, что после данного шага прочитанный префикс принадлежит заданному языку. Для произвольной таблицы Мили выходы могут отличаться от 0 и 1; лекционный пример использует 0, 1, 2, 3.

## 1.2 Распознавание слова и выходная последовательность

Слово распознаётся после обработки всех его символов. Если текущее состояние принадлежит F, слово допустимо. Промежуточное появление выхода 1 не означает, что любое продолжение слова также допустимо. Например, для a⟨b|c⟩d слово ad принимается, но add отклоняется: после первого d дальнейшее d переводит автомат в состояние отказа.

Для непустого слова в реализованном распознавателе последний выход совпадает с меткой конечности итогового состояния. Для пустого слова переходов нет, выходная последовательность пуста. Поэтому правило «последний выход равен 1» нельзя использовать без отдельной проверки начального состояния. Выражение ⟨a⟩ допускает пустое слово, хотя автомат не формирует ни одного выходного символа.

Для общего автомата Мили результатом считается выходное слово. Категории «допустимо» и «недопустимо» к нему не применяются, если множество конечных состояний не задавалось. В лекционном примере вход xyx даёт выходы 1, 0, 2; пустой вход даёт пустой выход. Программа сохраняет это различие между двумя режимами.

## 1.3 Способы задания автомата

Методичка ЛР №4 использует три представления: таблицы переходов и выходов, ориентированный граф и автоматную матрицу [1]. В объединённой таблице по строкам расположены состояния, по столбцам — входные символы. В ячейке записывается пара «состояние назначения / выход». Такое представление удобно для выполнения одного шага и проверки полноты задания.

На ориентированном графе вершина соответствует состоянию, а дуга помечается входом и выходом, например x/1. Начальное состояние отмечается входящей стрелкой. Конечные состояния распознавателя выделяются двойной окружностью. Если несколько входов ведут из одной вершины в одну и ту же вершину, их метки можно объединить на одной дуге, сохраняя связь каждого входа с его выходом.

В автоматной матрице строки и столбцы соответствуют состояниям. В ячейку (qi, qj) включаются метки всех переходов из qi в qj. Отсутствию дуги соответствует пустая ячейка. В отличие от таблицы переходов размер матрицы определяется числом состояний, а не размером входного алфавита. Матрица полезна для проверки связности и представления нескольких переходов между одной парой состояний.

Программа формирует все три представления. Табличные формы и графы строятся из одной структуры переходов, что исключает ручное расхождение между рисунком и таблицей. Экспорт SVG позволяет рассмотреть граф независимо от размера рабочей области окна.

## 1.4 Связь с другими изученными моделями вычислений

В ЛР №1 рассматриваются рекурсивные функции и способы построения вычислимых функций из базовых операций. Введённая там минимизация — μ-оператор поиска значения аргумента. Он не является алгоритмом сокращения числа состояний автомата и в настоящей работе для этой цели не используется [4].

В ЛР №2 машина Тьюринга содержит конечное управляющее устройство, головку и ленту. Наличие изменяемой ленты отличает её от рассматриваемого конечного автомата без дополнительной памяти. Из этой работы для практической части существенны требования явного задания переходов, пошаговой трассировки и диагностики ошибочного входа [5].

ЛР №3 рассматривает формальные системы Туэ и Поста: вычисление представляется последовательностью применений правил к словам. С автоматной моделью их объединяет работа с алфавитами и дискретными преобразованиями, но механизм вывода другой. Для программы настоящей работы принят тот же принцип проверяемого протокола: каждое изменение состояния связано с конкретным входом и выходом [6].

# 2 Синтез методом мест и подчинения

## 2.1 Регулярные выражения и принятые обозначения

В методичках символ | обозначает альтернативу, соседство выражений — конкатенацию, круглые скобки — группировку, а угловые скобки ⟨…⟩ — повторение ноль или более раз [2]. Следовательно, a⟨b|c⟩d описывает слова, начинающиеся с a, заканчивающиеся d и содержащие между ними произвольную последовательность букв b и c, включая пустую.

Программа поддерживает оба начертания итерационных скобок: ⟨…⟩ и <…>. Литерами служат отдельные латинские буквы и цифры. Пробельные символы в выражении удаляются до разбора. Дополнительно введено явно обозначенное расширение ε для пустого слова. Пустая ветвь a| и пустые скобки () считаются ошибками; вместо них необходимо явно записывать ε.

!eq R ::= C ( | C )*        C ::= T+        T ::= a | ε | (R) | ⟨R⟩

Грамматическая запись описывает синтаксические уровни разбора; символы * и + в этой строке относятся к описанию грамматики. В пользовательском выражении операции *, +, ?, диапазоны и экранирование не предусмотрены. Конкатенация имеет более высокий приоритет, чем альтернатива. Например, ab|c означает выбор между ab и c, а a(b|c) — конкатенацию a с результатом выбора.

## 2.2 Места и основные индексы

Место — позиция между соседними символами записи выражения, а также перед первым и после последнего символа. ЛР №5 предлагает различать все места, выделять основные и предосновные места, присваивать основные индексы и распространять их по отношению подчинения [2]. В программе зазоры нумеруются с нуля; это изменение способа нумерации не меняет отношений между ними.

Индекс 0 приписывается начальным местам исходного выражения. При альтернативе верхнего уровня начальных мест несколько, и они получают общий нулевой индекс. Каждому месту непосредственно после вхождения буквы присваивается очередной основной индекс. Два вхождения одной буквы получают разные индексы: они могут находиться в разных структурных контекстах и вести к разным продолжениям языка.

Предосновное место непосредственно предшествует конкретному вхождению буквы. Чтобы определить переход по этой букве, проверяется наличие индекса текущего состояния среди индексов предосновного места. Место после буквы задаёт основной индекс, включаемый в множество назначения. Таким образом, строится переход между множествами индексов, а не между символами выражения.

## 2.3 Правила подчинения

Первое правило относится к открывающим скобкам. Место перед открывающей обычной или итерационной скобкой подчиняет начальные места всех термов заключённой внутри альтернативы. За счёт этого индекс внешнего места может достигнуть начала любого выбранного терма.

Второе правило относится к закрывающим скобкам. Место после закрывающей скобки подчинено конечным местам всех термов внутри скобок. Для итерационных скобок оно также подчинено месту перед открывающей скобкой. Дополнительная связь позволяет пройти цикл ноль раз и сразу продолжить чтение выражения после него.

Третье правило относится к повторению: место после закрывающей итерационной скобки подчиняет начальные места всех термов цикла. Оно обеспечивает возможность нового повторения после завершения предыдущего. Эти связи не потребляют входной символ: чтение символа происходит только на переходе через соответствующее вхождение буквы.

Четвёртое правило — транзитивность: если место c подчинено b, а b подчинено a, то c подчинено a. Пятое — рефлексивность: любое место подчинено самому себе. Шестое правило запрещает вводить другие случаи подчинения. В программе сначала создаются непосредственные связи первых трёх правил, затем для каждого места вычисляется множество достижимых по ним мест с учётом самого исходного места.

Для ясности запись p→r в протоколе означает «r подчинено p». Направление распространения индекса совпадает с направлением этой стрелки. Такой выбор необходимо явно сохранять при построении таблицы: обратное прочтение отношения изменило бы результат синтеза.

## 2.4 Формирование состояний и переходов

Пусть I — множество основных индексов, а C(i) — множество мест, до которых распространяется индекс i. Состояние синтезируемого автомата представляется подмножеством B множества I. Начальное состояние имеет метку {0}. Для каждого входного символа рассматриваются все его вхождения в исходном выражении.

!eq D(B, x) = { j | перед x есть индекс из B, а после данного x стоит основной индекс j }

Если ни одно вхождение x не разрешено, получается пустое множество {}. Оно сохраняется как полноценное состояние отказа. Из него по каждому символу получается оно же. Это делает функцию переходов всюду определённой на выбранном алфавите и обеспечивает однозначный отказ при лишнем продолжении слова.

Состояние B отмечается как конечное, если хотя бы один его индекс достигает конечного места выражения. В общей формулировке ЛР №5 для нескольких выражений состояние могло бы иметь несколько меток. В программе вход содержит одно выражение, поэтому метка конечности имеет два значения: выражение завершено либо не завершено.

!eq λ(x, B) = 1, если D(B, x) конечно; иначе λ(x, B) = 0

Построение выполняется обходом достижимых подмножеств: для ещё не обработанного состояния вычисляются все переходы, новые множества включаются в очередь, а процесс продолжается до её опустошения. Перебирать все подмножества заранее не требуется. Равные множества представляются одним состоянием; разные множества до этапа минимизации не объединяются только по внешнему сходству поведения.

## 2.5 Обоснование корректности синтеза

Инвариант синтеза состоит в следующем: после чтения префикса множество основных индексов содержит окончания именно тех вхождений букв, которыми может завершаться этот префикс с учётом разрешённых структурных продолжений. Для пустого префикса действует индекс 0 начальных мест. Он распространяется через скобки и пропускаемые итерации, разрешая начальные символы языка.

Переход по символу x рассматривает все разрешённые его вхождения. Поэтому ни одно допустимое продолжение не теряется. Одновременно в множество назначения не включается индекс вхождения, перед которым нет активного индекса: произвольного перескока между ветвями не происходит. Объединение таких окончаний реализует детерминированную обработку нескольких возможных структурных разборов одного префикса.

Конечность состояния означает достижимость конца выражения после прочитанного префикса. Отсюда следует совпадение принятия слова с принадлежностью языку выражения. Программная проверка по независимому регулярному механизму не заменяет этот инвариант, но позволяет обнаружить неверную реализацию правил, в частности ошибочные связи между ветвями вложенной альтернативы.

## 2.6 Уточнение несогласованностей учебных примеров

В ЛР №4 для a⟨b|c⟩d слово ad приведено среди допустимых, но в таблице отсутствует необходимый переход после нулевого числа повторений, а последующая проверка объявляет это слово недопустимым. Там же abcd ошибочно указано как слово с лишним символом после d, хотя его последним символом является d. В ЛР №5 слово ad принимается, что соответствует определению итерации [1, 2].

В настоящей работе используются определения операций и формальные правила ЛР №5. Поэтому ad и abcd допустимы. Слово add недопустимо. Это сохраняет учебную методику и устраняет внутренние противоречия иллюстраций без подмены метода другим алгоритмом синтеза.

В примере ЛР №5 метка {1,2,3} сразу используется как одно состояние после a или букв цикла. При буквальном применении правила перехода из {0} по a сначала получается {1}; переходы по b и c дают {2} и {3}. Объединение этих состояний по одинаковому будущему поведению обосновано на следующем этапе — минимизации. В отчёте сырой синтез и сокращение эквивалентных состояний показываются раздельно.

# 3 Минимизация конечного автомата

## 3.1 Эквивалентность состояний Мили

Два состояния автомата Мили эквивалентны, если при подаче любой одинаковой входной последовательности из них получаются одинаковые выходные последовательности. Сравнивать только следующий переход или число исходящих дуг недостаточно: различие может проявиться после нескольких символов. Равенство выходов на одном шаге необходимо, но ещё не гарантирует эквивалентность [3].

Для распознавателя дополнительно требуется совпадение метки конечности состояний. Это условие отвечает за результат на пустом продолжении. При выходе, определяемом конечностью назначения, такой усиленный критерий сохраняет одновременно язык и все выходы. Если оставить только общий критерий Мили без метки конечности, можно было бы потерять различие между состояниями, которое наблюдается до первого перехода.

Минимальность относится к фиксированным входному алфавиту, начальному состоянию и принятому критерию наблюдения. В рассматриваемой задаче сокращается достижимая часть полного автомата. Внешний рисунок и обозначения состояний при этом могут измениться; содержание выходных слов и результат распознавания изменяться не должны.

## 3.2 Удаление недостижимых состояний

Состояние достижимо, если существует входное слово, переводящее в него автомат из начального состояния. Недостижимое состояние нельзя наблюдать при обычном запуске, поэтому оно удаляется до сравнения классов. Для синтеза обходом подмножеств такие состояния не создаются, но при загрузке таблицы Мили они возможны.

Алгоритм начинает с начального состояния и последовательно добавляет цели всех его переходов. Затем аналогично обрабатываются найденные состояния. После завершения обхода сохраняются только посещённые состояния. В протоколе отдельно перечисляются удалённые обозначения: это позволяет отличить удаление недостижимости от объединения эквивалентных состояний.

## 3.3 Начальное разбиение по выходам

Согласно лекционному примеру для каждого состояния записывается вектор выходов на всех входных символах в фиксированном порядке. Состояния с одинаковыми векторами помещаются в один класс. Это исходное разбиение P0. В режиме распознавания к вектору также добавляется признак принадлежности F.

!eq V(q) = ( λ(x1,q), …, λ(xk,q) )

Если выходы двух состояний различаются хотя бы на одном входе, этот односимвольный вход уже служит различающим словом. Поэтому объединение таких состояний изменило бы поведение. С другой стороны, одинаковые векторы означают лишь отсутствие различия на первом шаге: необходимо проверить, в какие классы попадают цели переходов.

## 3.4 Последовательное уточнение классов

Для текущего разбиения P каждому состоянию сопоставляется вектор номеров классов его целей. Внутри каждого существующего класса состояния разделяются по различию этих векторов. Уже разделённые классы не объединяются обратно. Получается следующее, не более грубое разбиение.

!eq T(P,q) = ( [δ(x1,q)]P, …, [δ(xk,q)]P )

Уточнение повторяется, пока состав классов не перестанет изменяться. В последнем шаге протокола разбиение повторяется, что явно показывает проверку устойчивости. Конечность процесса следует из того, что при каждом существенном уточнении число непустых классов увеличивается, а превысить число достижимых состояний оно не может.

Каждому устойчивому классу ставится в соответствие одно состояние минимального автомата. Начальным становится класс исходного начального состояния. Цель перехода определяется классом цели любого представителя, а выход берётся из исходной таблицы. Устойчивость и одинаковые выходные векторы гарантируют, что выбор представителя не влияет на результат.

## 3.5 Почему результат минимален

В начальном разбиении разделены состояния, различимые по выходу на слове длины один, а для распознавателя — также по пустому продолжению. Каждое следующее уточнение отделяет состояния, из которых один и тот же вход ведёт в уже различимые классы. К различающему слову целевых состояний добавляется первый символ, поэтому разделение имеет наблюдаемую причину.

В устойчивом разбиении внутри класса совпадают выходы и классы переходов на всех входах. По индукции по длине входного слова совпадают все будущие выходы; для распознавателя совпадает и конечность после любого продолжения. Поэтому состояния одного класса действительно эквивалентны, а состояния разных классов объединить без изменения поведения нельзя.

В качестве отдельного контроля программа обходит произведение исходного и минимального автоматов. Если в достижимой паре обнаружены разные метки конечности либо разные выходы на одном входе, строится различающее слово. Если проверены все достижимые пары и различий нет, установлена эквивалентность на всех словах выбранного алфавита, а не только на перебранных тестовых цепочках.

## 3.6 Затраты алгоритмов

При n вхождениях букв возможны до 2ⁿ⁺¹ подмножеств основных индексов. Для конкретного выражения достижима лишь часть из них, но в общем случае экспоненциальный рост исключать нельзя. Поэтому программа ограничивает длину выражения, вложенность и число созданных состояний. Превышение лимита заканчивается диагностикой, а не выдачей усечённого автомата.

Вычисление замыкания выполняется обходом графа подчинения из каждого места. Для v мест и e непосредственных связей такая реализация требует порядка v(v+e) операций обхода. Она выбрана ради прозрачности учебного протокола: каждая строка содержит фактически найденные подчинённые места.

Пусть m — число достижимых состояний, k — размер входного алфавита. Один проход уточнения обрабатывает mk переходов. Существенных уточнений не более m−1, поэтому простая реализация имеет верхнюю оценку O(km²). Проверка произведением посещает не более m·r пар для автоматов размеров m и r и исследует k переходов каждой пары. Для учебных автоматов такая реализация наглядна и достаточна.

# 4 Практические примеры синтеза и минимизации

## 4.1 Постановка практической задачи

Необходимо создать программу, которая читает регулярное выражение в обозначениях методички либо полную таблицу Мили, строит исходный автомат, минимизирует его, показывает промежуточные данные, проверяет слова и сохраняет результаты в файлы. Основным примером синтеза выбрано a⟨b|c⟩d, поскольку он непосредственно присутствует в обеих методичках и позволяет проверить нулевое число повторений.

Второй пример воспроизводит лекционную таблицу Мили с алфавитом {x,y}, пятью состояниями и выходами {0,1,2,3}. Он необходим, чтобы проверить минимизацию именно выходного автомата, а не только распознавателя с двоичным признаком принятия. В качестве дополнительного источника выражений используются все 30 вариантов ЛР №5, включая вариант 20.

## 4.2 Разметка и подчинение для основного выражения

Эти же индексы достигают предосновных мест b и c благодаря обратной связи повторения.

# 5 Программная реализация и руководство пользователя

## 5.1 Состав программы

Ядро core.py не зависит от графического интерфейса. В нём находятся класс Machine, разбор выражения, построение графа подчинения, синтез подмножеств, проверка таблицы Мили, минимизация, трассировка и точное сравнение. Разделение позволяет запускать одни и те же алгоритмы из окна, тестов и экспериментального сценария.

Модуль storage.py отвечает за чтение UTF-8, текстовые таблицы, автоматные матрицы и графы SVG. Модуль app.py создаёт окно Tkinter и вызывает функции ядра из обработчиков действий пользователя. tests содержит автоматические проверки, experiments.py сохраняет результаты экспериментов, а qa_visual.py выполняет каталог сценариев интерфейса. Полные листинги приведены в приложениях.

В структуре Machine входы и состояния имеют фиксированный порядок. Для каждой строки переходов хранится словарь входов, а значение является парой «цель, выход». Конечные состояния хранятся отдельно. Поле details существует для протокола синтеза и содержит места, подчинение и сырые подмножества. Оно не требуется для выполнения уже построенного автомата.

## 5.2 Запуск и основные действия

Для запуска нужен Python 3.12 или более новая совместимая версия с Tkinter. На обычной установке Python для Windows этот интерфейс доступен вместе с интерпретатором. Сторонние пакеты для самой программы и тестов не требуются. В каталоге проекта необходимо выполнить python app.py либо открыть файл запуска Run.cmd.

В верхней части окна выбирается режим «РВ» или «Мили JSON». Ниже находится поле исходных данных. Кнопки примеров загружают основной пример из ЛР №5 и лекционный автомат. Кнопка «Построить» запускает полный цикл: разбор, синтез или проверку таблицы, минимизацию и проверку эквивалентности.

Вкладка «Автоматы» показывает исходную и минимальную таблицы и автоматную матрицу. Вкладка «Графы» позволяет переключать исходный и минимальный граф. Вкладка «Места» показывает распространение индексов, «Разбиения» — последовательность уточнений и соответствие состояний классам. Вкладки «События» и «Справка» содержат журнал и описание синтаксиса.

Чтобы проверить слово, нужно открыть вкладку «Проверка слова», ввести последовательность и нажать «Проверить». Пустое поле означает ε. Пробел в слове сохраняется и проверяется как обычный входной символ. Отображаются обе траектории, выходы и результат сравнения. Если автомат ещё не построен, программа предлагает сначала выполнить построение.

## 5.3 Формат входных файлов

Текстовый файл с расширением .txt содержит одно регулярное выражение. Допускается кодировка UTF-8 с BOM или без него. Импорт .json переключает интерфейс в режим Мили. Файл сначала загружается в поле ввода, после чего пользователь может проверить содержимое и нажать «Построить».

Для JSON обязательны поля alphabet, states, start и transitions. В каждой строке transitions должны присутствовать все входные символы и отсутствовать посторонние. Цель обязана принадлежать states, выходом может быть непустая строка либо целое число. Числовые выходы приводятся к строкам, чтобы сравнение не зависело от способа записи 1 или "1".

Необязательное поле recognizer включает режим распознавания. При его значении true поле finals перечисляет конечные состояния, а выход каждого перехода обязан равняться 1 для конечной цели и 0 для неконечной. Это проверяемое условие сохраняет смысл экспортированного распознавателя. В обычном режиме Мили finals не используется.

## 5.4 Экспорт результатов

Кнопка «Экспорт комплекта» предлагает выбрать каталог и записывает пять файлов: original.json, minimal.json, protocol.txt, original.svg и minimal.svg. JSON можно повторно загрузить как входной автомат; текстовый протокол содержит таблицы, матрицы, разбиения, отображение состояний и результат точной проверки. SVG хранит граф в масштабируемом виде.

Повторный экспорт в тот же каталог использует те же имена. Поэтому для сохранения нескольких независимых экспериментов следует выбирать отдельные каталоги. Если запись завершилась ошибкой, программа сообщает о ней; частично записанный комплект нельзя считать полным результатом. После успешного экспорта в интерфейсе указывается число сохранённых файлов.

## 5.5 Ошибки, ограничения и состояние интерфейса

Для выражения установлен предел 300 значащих символов и 40 уровней скобок. По умолчанию разрешено построить до 256 состояний; параметр задаётся целым числом от 1 до 512. Таблица JSON допускает до 512 состояний и 62 односимвольных входов. Максимальный размер входного файла равен 32 МБ, максимальная длина проверяемого слова — 10 000 символов. Эти ограничения согласованы для синтеза и повторного импорта.

При синтаксической ошибке выводится её позиция. Для JSON отдельно обрабатываются ошибки записи, структуры таблицы и ограничения самого парсера на глубину и длину числа. Отсутствующий файл, неверная кодировка, превышение размера и невозможность записи преобразуются в диагностическое сообщение. Рабочее окно после таких ошибок остаётся доступным.

Изменение исходных данных сбрасывает построенный автомат, таблицы и трассу. Это предотвращает проверку слова по результату, уже не соответствующему видимому входу. После успешного импорта также нужно выполнить новое построение. Отмена открытия или экспорта не меняет текущий автомат. Очистка удаляет исходный текст и результаты.

Встроенный граф ограничен отображением до 40 состояний; для большего автомата программа предлагает экспорт SVG. Даже при небольшом числе состояний плотный граф может быть менее удобен, чем таблица. Автоматная матрица растёт квадратично по числу состояний, поэтому при работе с большими примерами полезно использовать текстовый экспорт и прокрутку.

# 6 Проверка корректности и результаты испытаний

## 6.1 Стратегия проверок

Для произвольных регулярных выражений и слов невозможно перечислить все входные данные. В испытаниях задаются конечные проверяемые области и отдельный каталог событий программы. Полнота перебора относится только к явно указанному алфавиту, длине слова и набору выражений. При этом проверка эквивалентности произведением автоматов является точной для конкретной построенной пары.

Первый уровень составляет модульное тестирование: операции ядра, ограничения и валидация данных. Второй уровень — сравнение с независимым механизмом re.fullmatch. Для него обозначения итерации преобразуются в обычную запись, а соответствующий механизм используется только как тестовый оракул, не участвуя в синтезе программы [7]. Дополнительно проверяется выход для каждого префикса слова.

Третий уровень — точная проверка эквивалентности исходного и минимального автоматов. Четвёртый — интеграционные сценарии интерфейса, файловых операций и восстановления после ошибок. Ожидаемые результаты в сценариях задаются явно, а проверки выполняются над реальным объектом App и содержимым его виджетов. При автоматизации файловых сценариев диалог выбора пути изолирован: тест возвращает заданный путь либо отмену, а чтение и запись выполняются обычным файловым слоем.

## 6.2 Автоматические тесты

!data unittest

Проверяется основной пример, лекционная минимизация 5→3, нулевое число повторений, пустое слово, повторяющиеся буквы в разных местах, вложенные группы и альтернативы, неизвестный вход и состояние отказа. Для минимизации проверяются удаление недостижимого состояния, несколько раундов уточнения, сохранение выходов и повторная минимизация уже минимального результата.

Отрицательные проверки охватывают пустой ввод, пустые скобки, незакрытые и лишние скобки, пустую альтернативу, посторонние операции, превышение длины и вложенности, неверные лимиты. Для JSON проверяются тип корневого значения, уникальность имён, алфавит, начальное состояние, набор строк и столбцов, цель перехода, тип выхода и поля распознавателя.

Файловые проверки создают реальные временные файлы, сохраняют комплект, повторно читают оба JSON и проверяют их эквивалентность исходному автомату. Отдельно проверяются отсутствие файла, нарушение UTF-8, слишком большой файл и путь сохранения, занятый обычным файлом. Тесты интерфейса проверяют последовательность «успех — ошибка — повторный успех» и сброс результата.

## 6.3 Все варианты ЛР №5

Для каждого из 30 выражений перебраны все слова длины от нуля до четырёх включительно над алфавитом данного выражения. Принятие каждого слова сравнивается с независимым оракулом. Для слов в алфавите также сопоставляются все выходные сигналы с принадлежностью соответствующих префиксов языку. Результаты сведены в таблицу; расширенный CSV содержит каждую проверенную цепочку.

!data variants

Число проверок различается из-за размера алфавита. При k символах перебирается 1+k+k²+k³+k⁴ слов; единица соответствует ε. Такая область содержит короткие допустимые и недопустимые цепочки, многократные повторения отдельных букв и комбинации букв из разных частей выражения. Она не претендует на перебор всех длин, поэтому дополняется другими уровнями проверки.

## 6.4 Сгенерированные выражения и независимый контроль

Дополнительный набор содержит 120 выражений с фиксированным зерном генератора 4332. Генератор сочетает конкатенацию, альтернативу, итерацию и ε на глубине три. Для каждого выражения перебраны все слова над {a,b} длины от нуля до пяти, то есть 63 слова. Если символ не принадлежит собственному алфавиту построенного автомата, ожидается отказ; сравнение выходов проводится для слов внутри алфавита.

!data experiment_summary

Независимый тест синтеза принципиален: совпадение исходного и минимального автоматов само по себе не исключает общей ошибки построения. Если оба автомата распознают неверный язык, проверка произведением всё равно подтвердит их взаимную эквивалентность. Поэтому в результатах раздельно учитываются соответствие выражению и сохранение поведения при минимизации.

## 6.6 Границы сделанных выводов

Все зарегистрированные автоматические проверки завершились без расхождений. Это подтверждает результаты на описанных наборах и исполнение каталога событий. Из этого не следует безусловная корректность для любых возможных данных, любой версии Python или при любом состоянии операционной системы.

Точная проверка произведением относится ко всему множеству слов конкретного входного алфавита для двух конечных таблиц. Математическое обоснование синтеза опирается на инвариант распространения индексов, а минимальности — на устойчивое разбиение. Экспериментальные данные дополняют эти рассуждения, но не подменяют их.

В программу не входят недетерминированные таблицы, автоматы Мура, многосимвольные входные токены, расширенный синтаксис библиотечных регулярных выражений и обработка нескольких независимых выражений с разными выходными метками. Эти возможности не нужны для воспроизведения выбранной методики и потребовали бы отдельной постановки задачи.

Выполнено исследование синтеза и минимизации конечного автомата с опорой на предоставленные учебные материалы. Сохранены метод мест и подчинения ЛР №5, три формы задания автомата из ЛР №4 и лекционная последовательность минимизации Мили. Неоднозначности иллюстраций разрешены в пользу формальных правил: итерация допускает ноль повторений, а сырые множества индексов отделены от последующего объединения эквивалентных состояний.

Практический результат — программа с графическим интерфейсом, позволяющая исследовать каждый этап преобразования. На основном примере полный автомат сокращён с шести состояний до четырёх, а в лекционном примере — с пяти до трёх. Для распознавателя сохраняются язык, пустое слово и последовательности выходов; для общей таблицы Мили сохраняются выходные слова.

Корректность проверена модульными и интеграционными тестами, независимым перебором всех коротких слов для 30 учебных и 120 сгенерированных выражений и точным сравнением автоматов. Протоколы, исходники, CSV с результатами и примеры входных данных позволяют повторить вычисления. Тем самым программа служит не только средством получения минимальной таблицы, но и проверяемым учебным инструментом для анализа метода.
